# NNOV Клиника

Интерактивный прототип IT-продукта для управления клиникой. Он связывает показатели, проблемные ситуации, задачи команды и результат: от обращения и свободного окна до оказанной услуги и подтверждённой оплаты.

Текущая версия: **0.4.0**. Бренд: **NNOV.RU**. Два независимых демонстрационных сценария - стоматология «Имплант52» и медицинский центр «Эндо360». Все пациенты, события, суммы и диалоги вымышлены.

## Что изменилось в v0.4

Первый сценарий выделен в очередь координатора: причина сигнала, договорённость пациента, ответственный, поручение и подтверждённый организационный исход. Паузы, отказ, действующие записи и неполные данные показываются отдельно. Отмена записи возвращает случай к проверке. Это развитие прототипа по результатам разбора конкурентов до практического пилота.

Ядро и текстовая презентация обновлены до версии 0.2 внутри docs/. Предполагаемое преимущество удобства, качества обработки исключений и меньшей нагрузки пока не подтверждено.

## Запуск

Откройте `index.html` в браузере. Приложение полностью автономно: зависимости, сервер и доступ в интернет для демо не нужны.

Для разработки нужен Node.js 22 или новее:

```sh
npm run build
npm run check
```

Сборка создаёт одинаковые `index.html` и `dist/index.html`. В GitHub хранится корневой HTML; `dist/` пересоздаётся локально. Команда проверки собирает приложение, запускает существующие проверки бизнес-логики и сверяет экспорт.

## Что есть в продукте

| Раздел | Основная функция |
| --- | --- |
| Пульс клиники | Показатели дня, отклонения, приоритетные действия |
| Ассистент | Сводка, объяснение показателей, предложения задач и переходы к основаниям |
| Загрузка и спрос | Расписание, свободные окна, назначенные этапы |
| Обращения | Возврат обращений, запись, визит, оплата, причина закрытия |
| Планы лечения | Решение пациента, координатор, этапы, записи, выполнение, частичные оплаты |
| Экономика | Оказанные услуги, поступления, расходы, остатки к оплате, сценарный расчёт |
| Команда и качество | Разбор диалогов, ошибки, задачи и проверка применения |
| Обучение | Упражнения, попытки, результаты и база знаний |
| Сопровождение | Получение инструкций, подтверждения, вопросы, передача специалисту |
| Задачи | Ответственный, срок, состояние и история действий |
| Результаты | Записи, состоявшиеся визиты и поступления раздельно |
| Качество данных | Полнота, согласованность, определения и ограничения расчётов |
| Карта продукта | Презентационный сценарий и предполагаемый пилот |

Предусмотрены три рабочих места: руководитель, администратор и координатор. Переключение рабочего места меняет интерфейс. Это демонстрация ролей, серверной авторизации пока нет.

## Основные конструкции

- Управленческий цикл: сигнал → основание → ответственный → задача → действие → визит / услуга / оплата → проверка результата.
- Единая модель событий: запись, выполнение услуги и поступление денег являются разными событиями.
- Планы состоят из этапов: запись меняет расписание, выполнение добавляет услугу, оплата уменьшает остаток.
- Экономика использует стоимость оказанных услуг, прямые расходы и постоянные расходы. При отсутствии затрат полный результат не рассчитывается.
- Ассистент читает текущее состояние демо. Создание задачи требует отдельного нажатия, повторные и устаревшие предложения проверяются.
- Прогресс и история чата сохраняются в браузере; клиники и рабочие места имеют отдельные контексты.

## Публикация через GitHub Pages

Текущее размещение подготовлено в `klima3567-sketch/r52-public`, каталог `nnov-clinic/`. GitHub Pages этого репозитория использует `main` и `/ (root)`; продукт открывается по подпути `/r52-public/nnov-clinic/`. Сборка выполняется из `nnov-clinic`, проверка запускается корневым workflow `nnov-clinic-check.yml`.

Ниже - настройка для размещения этого исходного проекта как самостоятельного репозитория.

В настройках репозитория выберите **Pages → Deploy from a branch → main → / (root)**. Точкой входа служит корневой `index.html`, файл `.nojekyll` отключает обработку Jekyll. При изменениях исходников выполните `npm run check` и закоммитьте обновлённый `index.html` вместе с исходниками.

## Статус

Это работающее интерактивное демо, а не подключённая к клинике информационная система. Ассистент использует правила, языковая модель не подключена. Интеграции с МИС, серверное хранение, настоящие права доступа, отправка сообщений и фоновые уведомления относятся к следующим этапам. Медицинские решения остаются у специалистов. Цены и экономический эффект продукта пока являются гипотезами.
