# Модель данных

## Основные сущности

| Сущность | Назначение | Связь |
| --- | --- | --- |
| Клиника | Изолированный демонстрационный сценарий | DB.implant / DB.endo |
| Обращение / ситуация | Потенциал записи и следующего действия | Ответственный, задача, визит и оплата |
| План | Согласованный врачом маршрут в представлении демо | Решение пациента, координатор, этапы |
| Этап плана | Отдельное организационное выполнение | Запись, состояние выполнения, сумма и paid |
| Услуга | Тип услуги и её прямые затраты | Стоимость, труд, материалы, внешние работы |
| Журнал услуг | Факт выполненной услуги | ID, день, тип услуги, количество, сумма, paid |
| Управленческая задача | Организационное поручение | Источник, ответственный, срок и состояние |
| Диалог | Сценарий для разбора качества | Проверка, задача и упражнение |
| Обучение | Попытки и результаты упражнения | Сотрудник, тема, прохождение |
| Сопровождение | Получение инструкции и вопросы | Доставка, подтверждение, эскалация, закрытие |
| Событие | История действий внутри демо | Действие и время/подпись модели |
| Поток ассистента | История и текущий контекст | Клиника, рабочее место, сообщения и предложения |

## События и финансовые правила

1. Назначение этапа занимает окно расписания и не увеличивает выручку.
2. Выполнение этапа добавляет оказанную услугу. Повторное выполнение блокируется.
3. Оплата увеличивает поступления и уменьшает остаток. Частичная оплата разрешена, сверхоплата блокируется.
4. Сумма плана содержит будущие этапы и не считается целиком оказанной услугой.
5. Прямые расходы = оплата специалистов + материалы + внешние работы на единицу, умноженные на объём.
6. Маржинальный доход = начисления за оказанные услуги минус прямые расходы.
7. Промежуточный операционный результат = маржинальный доход минус постоянные расходы. Это результат до налогов, не чистая прибыль.
8. При неизвестных материалах полный финансовый результат скрывается до ввода значения с основанием.

Постоянные расходы заданы за полный месяц, а журнал ограничен 1-27 октября. Сравнение с итоговой месячной прибылью некорректно без закрытия периода.

## Ограничения модели

Ресурсы расписания представлены часовыми блоками на этап. Прохождение обучения не создаёт финансовый эффект автоматически. Доля пройденных проверок качества не является вероятностью достоверности данных. Калькулятор сценария сохраняет структуру услуг и постоянные расходы; изменение цен, материалов и объёма остаётся допущением.

Для будущих интеграций потребуются единые внешние ID, история синхронизации, различение времени события и загрузки, правила дублей и явная сверка источников. Эти механизмы пока не реализованы.
