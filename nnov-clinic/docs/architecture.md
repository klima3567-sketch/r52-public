# Архитектура

## Текущая реализация

Обычные HTML, CSS и JavaScript без фреймворка, сервера и внешних пакетов. Сборка объединяет исходники в автономный документ. Один и тот же HTML можно открыть локально или разместить на GitHub Pages.

| Слой | Файл | Ответственность |
| --- | --- | --- |
| Оболочка | src/template.html | Каркас, навигация, модальные окна, базовые стили |
| Базовые процессы | src/clinic-base.js | seed(), обращения, расписание, состояния карточек, визит и оплата |
| Расширение продукта | src/clinic-suite.js | suiteSeed(), планы, финансы, роли, сопровождение, обучение, сохранение и экспорт |
| Ассистент | src/clinic-assistant.js | assistantAnswer(), приоритеты, история, актуальность и исполнение предложений |
| Следующий шаг | src/clinic-workflow.js | Очередь случаев, договорённости, актуальность, поручения и подтверждение исходов |
| Оформление | src/suite.css, src/assistant.css, src/workflow.css | Разделы, адаптивность, полный чат и компактная панель |
| Сборка | scripts/build.mjs | Проверка синтаксиса, вставка CSS/JS, два одинаковых выходных HTML |
| Проверки | scripts/verify.mjs | Выполнение бизнес-сценариев в изолированном VM-контексте |

Скрипты выполняются последовательно в общей области видимости. Расширение дополняет NAV/ROLES и использует функции предыдущего слоя. Это устройство демонстрационного прототипа; модули ES и API пока не выделены.

## Обновление состояния

Обработчик интерфейса проверяет допустимость действия, меняет модель выбранной клиники и вызывает пересчёт/рендер. persist() сохраняет браузерное состояние. Ассистент сравнивает подпись текущих данных с предыдущим снимком, обновляет сводку и отмечает старые ответы как устаревшие. Переключение экрана само по себе не создаёт повторную сводку.

## Хранение

Общий ключ localStorage: nnov-clinic-suite-v2. Формат рабочего состояния: schema-2. Слой ассистента использует собственную schema-1 и потоки по рабочим местам внутри выбранной клиники. При невозможности сохранения приложение продолжает работу в памяти вкладки.

Прогресс, накопленный на прежнем домене, автоматически не переедет на GitHub Pages: localStorage привязан к origin браузера. Копируется код и исходная модель. Кнопка выгрузки JSON не является готовой функцией восстановления из файла.

## Границы интеграций

Запросы в МИС, модель ИИ, почту, телефонию и мессенджеры отсутствуют. Внешние изображения и шрифты не используются. Флаги отправки и согласия - события модели. Роли и раздельные чаты не являются серверной изоляцией данных.

## Точки развития

Для рабочего продукта нужно вынести состояние в backend, определения показателей - в доменный слой, интеграции - в адаптеры источников, действия - в проверяемые команды. Ассистенту предоставлять ограниченный слой чтения и предложения команд, а не прямой доступ к изменениям. Выбор стека, API и инфраструктуры остаётся отдельным решением.

## Слой следующего шага v0.4

clinic-workflow.js загружается после ассистента. Он дополняет состояние плана workflow.schema=1, переиспользует этапы/записи/платежи и заменяет представление раздела планов очередью. Проверка исходов выполняется перед render(). Поручения следующего шага содержат ссылку на версию плана, собственный срок dueAt и доказательство исхода. Отмена записи возвращает такое поручение в работу; смена версии завершает прежнее как устаревшее. Демо-время зафиксировано 27 октября 2026, 15:00 МСК. Модель не читает реальные события МИС.
