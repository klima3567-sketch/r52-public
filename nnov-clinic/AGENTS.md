# Работа с NNOV Клиника

## Контекст

Это отдельный продукт NNOV.RU для клиник, версия 0.4.0. Он не является системой CJM Implant52. Два сценария с названиями клиник содержат только вымышленные данные.

Перед изменениями прочитайте README.md и соответствующие документы в docs/. Сохраняйте функциональность всех 13 разделов и трёх рабочих мест.

Для позиционирования, аудитории и презентаций сначала читайте docs/product-core.md и docs/presentation-text.md. Сегменты, JTBD и первый процесс в ядре являются гипотезами до явной обратной связи пользователя и проверки клиентами. Первым сегментом предложены частные стоматологии, первым процессом - планы без следующего согласованного организационного шага. Не выдавайте эти предложения за уже принятые решения или результаты исследования. Возможности прототипа сверяйте с исходниками; не обещайте существующие интеграции, подключённую нейросеть, реальные права или подтверждённый экономический эффект.

## Исходники и сборка

- Редактируйте src/, а не сгенерированный index.html.
- Порядок выполнения скриптов: clinic-base.js → clinic-suite.js → clinic-assistant.js → clinic-workflow.js. Общая область видимости намеренная; её изменение требует проверки зависимостей.
- После изменений запускайте npm run check. Коммитьте сгенерированный index.html вместе с изменёнными исходниками.
- Сохраняйте автономность HTML, отсутствие внешних ассетов и работу с путём проекта GitHub Pages.
- Не переносите служебную конфигурацию прежнего хостинга, учётные данные, личную память пользователя и реальные данные клиник в этот репозиторий.

## Первый сценарий v0.4

В docs/pilot-plan.md описана практическая проверка. T01-T12 в scripts/verify.mjs проверяют только вымышленную модель NNOV, а не DentalPRO или Statum. Новый слой хранит workflow.schema=1 внутри каждого плана и сохраняет рабочую schema-2. Не удаляйте прежние решения и финансовый прогресс при миграции. Договорённость с пациентом и срок поручения сотруднику - разные поля.

## Инварианты

- Запись, оказанная услуга и поступление оплаты учитываются отдельно.
- Полная сумма плана не равна выручке. Оплата не равна прибыли.
- Не заменяйте неизвестные расходы нулём; не показывайте полный результат при неполных данных.
- Не допускайте повторного выполнения этапа, сверхоплаты и выполнения будущих этапов.
- Прохождение обучения само по себе не меняет выручку и конверсию.
- Ассистент не назначает лечение и не создаёт задачи без отдельного действия пользователя.
- Сохраняйте защиту от дублей, проверку актуальности предложений и экранирование пользовательского текста.
- Рабочие места являются интерфейсными режимами, а не защитой доступа.
- Ключ localStorage nnov-clinic-suite-v2 и существующий прогресс schema-2 сохраняйте совместимыми или добавляйте явную миграцию.

## Формулировки

Пишите NNOV.RU латиницей. В русских текстах используйте дефис вместо длинного тире. Различайте реализованное демо, предложение и будущую интеграцию. Не обещайте непроверенный рост прибыли и не называйте правила ответов подключённым ИИ.
